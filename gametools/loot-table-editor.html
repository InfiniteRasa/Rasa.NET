Loot Table Editor

Profiles

    Keys are lowercase ASCII, digits, "_" or "-". Empty profiles explicitly mean no ordinary items.

    Profile and group settings

    Groups

    Admission is tested once per group, independently of candidate weights.

    Weighted candidates

    Weights are conditional on an admitted group and each roll. They are not drop percentages. Rolls sample with replacement; quantity bounds are inclusive.

    Use native IDs from World. Server validation checks quality, augmentations, inventory, stack limits and required-map coverage.

    Map / creature -> profile

    One profile per map and native creature row. To suppress ordinary items, bind an empty profile. Unnamed bindings are retained by the server.

    Edit bindings and map policies

    Map policies

    Required maps must cover every eligible native spawn, arrival, garrison and mission scene source. Existing required policies cannot be disabled here.

    Game server

    Project file

    Weighted format rasa-weighted-loot-profiles, version 2. This browser keeps your draft separately from old flat projects. Save a file for backup or review. No secret settings are included.

    Checks

    Local checks cover structure and numeric bounds only. The server's canonical catalog performs native-item and required-map validation before commit.

      Database rows

      Five existing canonical tables: loot_profile, ordinary_loot_group, loot_item, creature_loot_binding and loot_map_policy. The export updates named profiles and preserves unnamed bindings. Review and validate offline before applying; SQL cannot publish a running catalog.

      Choose the database you will apply this export to. MySQL uses UTF-8 hex text, independent of backslash SQL mode.
